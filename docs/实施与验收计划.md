# 项目三实施与验收计划

目标是完成课程文件中项目三的必做内容、四项拓展和结题交付。系统负责理解问题和建议后续知识源，不直接编造检修限度或替代规程回答。

## 实施顺序

1. 保存修改前的40条样本及原始预测，建立可复查基线。
2. 阅读原始PDF，建立术语来源索引；纠正别名混淆和样本中的推断性标签。
3. 明确分类、实体、完整性、澄清和路由契约，完善规则与LLM接口。
4. 修复批量评估，记录全部样本、错误、实体精确率/召回率/F1、分类和路由准确率、实际调用来源及耗时。
5. 完善中文前端，检验输入、模式切换、高亮、结果卡片、回退提示和导出。
6. 使用固定的校准样本评估新旧代码；增加未用于规则修改的独立测试题，单独报告结果。
7. 输出评估图表、错误分析、项目报告、演示PPT和演示流程。
8. 从干净启动、测试、数据来源、实验记录、文档渲染逐项验收。

当前状态以[项目三逐项验收记录](项目三逐项验收.md)为准。下表为最初规划，不作为现行完成结论。

## 实验约束

- 原始基线固定在 `evaluation/baseline/original_rules.json`，不覆盖。
- 样本修订必须记录理由，不按照当前程序预测反向生成标准答案。
- 旧样本只有部分实体标签，不能将未标注项直接当作不存在；实体完全匹配和F1仅用于完成全量标注的数据。
- 离线回退只说明容错有效，不算在线模型效果。没有真实调用时报告明确标注未测，不写预设的优劣结论。
- 代码注释解释规则依据、边界和设计取舍，删除重复描述代码流程的装饰性注释。
