# 2号成员数据交付说明

## 交付范围

本次只维护 2 号成员负责的数据部分：

- `data/terminology.json`：动车检修领域术语词典。
- `data/questions.json`：问题理解测试样本集。

未修改大模型接口、前端页面、评估脚本和其他成员负责的核心模块。

## 数据来源

- 课程要求来自 `doc/《铁路信息技术专业实践》2026课程实践项目V1.1.docx` 中“项目三：面向动车检修问答的问题理解与处理建议系统开发”。
- 检修术语依据 `doc/和谐2C型动车组四级检修规程.pdf`，并参考仓库内 `doc/项目三开发框架.md` 对 PDF OCR 后的章节梳理。
- 团队协作边界依据 `docs/TEAM_PROTOCOL.md`，数据格式沿用现有 JSON 字段，未新增顶层结构。

## 术语词典整理方法

词典按当前系统接口保留 5 类：

- `部件`：轮对、车轮、车轴、轮对轴箱装置、轴箱轴承、轴箱弹簧、一系悬挂装置等，并补充部分同章高频部件。
- `故障或现象`：裂纹、异响、磨损、腐蚀、划伤、剥离、电蚀、发热、老化、超限等。
- `工艺`：外观检查、清洗、磁粉探伤、超声波探伤、打磨、压装、退卸、组装、注油、动平衡试验等。
- `指标`：轮径、轮径差、轮对内侧距、划伤深度、剩磁量、过盈量、弹簧高度差、绝缘电阻等。
- `单位`：mm、μm、MPa、kPa、kN、N·m、mT、MΩ、g·m、℃、%、min、h 等。

每个标准词后面放常见简称、口语说法或同义表述，方便规则模块做别名归一化。

## 样本集设计方法

`questions.json` 保留 40 条样本，覆盖课程要求的场景：

- 完整检修问题：如标准限度、故障诊断、工艺流程、超限处置。
- 口语化问题：如“轴箱有点响”“轴承要不要换”。
- 信息不完整问题：如“这个超了怎么办”“轴承要不要换”。
- 非动车检修问题：如天气、汽车轮胎压力、泛泛速度问题。

为保证能直接接入现有系统，样本只使用仓库配置中的合法问题类型：

- `标准限度问题`
- `故障诊断问题`
- `工艺流程问题`
- `超限处置问题`
- `非动车检修问题`

处理标签只使用：

- `RAG`
- `KG`
- `CLARIFY`
- `OUT_OF_SCOPE`

## 注意事项

- 不建议在未通知 1 号成员前改变 JSON 顶层结构。
- 如果后续 3 号成员扩展规则模块，可以再把 `部件信息问题`、`条件判断问题`、`概念解释问题` 加入配置和样本。
- 当前 PDF 是扫描版，直接文本抽取为空；术语依据仓库中 OCR 梳理文档和课程要求整理，后续若重新 OCR，可继续补页码级来源表。
