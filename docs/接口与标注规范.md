# 接口与标注规范

本文件描述当前实现。页码、分类数量和枚举以本文件、术语来源表及当前代码为准；过时的开发草稿不随最终源码交付。

## 系统边界

输入是一个自然语言问题，输出是问题类型、已出现实体、标准化实体、缺失信息、澄清提示、置信度和处理建议。RAG、KG只是下一步知识源标签，本项目没有实现检索答案或图谱查询执行器。完整性表示是否足够构造查询，不代表足够作出维修决定。

## 公共入口

`main.analyze(question, mode)` 接受 `rules`、`llm`、`hybrid`。空白输入和非法模式抛出ValueError。页面与评估程序只调用此入口。

| 字段 | 含义 |
|---|---|
| 原始问题 | 去除首尾空白的输入 |
| 问题类型 | 下表8类之一 |
| 已识别信息 | 6类实体，每类是原始词与标准词对象数组 |
| 标准化信息 | 用词典统一后的实体；未知词保留模型给出的标准词 |
| 缺失信息 | 需要补充的字段名数组 |
| 信息完整性 | 完整、信息不足、非本领域问题 |
| 澄清提示 | 信息不足时的补充语句，其他情况为空 |
| 处理建议 | 标签与理由；标签为RAG、KG、CLARIFY、OUT_OF_SCOPE |
| 置信度 | 0到1的有限数值；是匹配强度或模型自评，未经概率校准 |
| 处理模式 | 用户请求的处理方式 |
| 运行耗时 | 规则耗时、在线尝试耗时、后端总耗时，单位ms |
| 元数据 | 实际来源、是否回退、回退原因、规则分阶段耗时等 |

## 分类与完整性

| 类型 | 主要意图 | 查询需要的信息 | 完整时路由 |
|---|---|---|---|
| 标准限度问题 | 多少、标准、何时更换 | 指标；部件明确的更换条件查询可不另填指标 | RAG |
| 故障诊断问题 | 原因、故障表现 | 部件和现象；主动询问故障表现时允许没有已知现象 | KG |
| 工艺流程问题 | 步骤、如何操作 | 工艺或部件；只有现象与工艺而无对象时补部件 | RAG |
| 超限处置问题 | 缺陷或超限后怎么办 | 部件，加指标或明确现象 | RAG |
| 条件判断问题 | 给定实测条件下是否处理 | 部件和指标/现象，数值已给但单位缺失时补单位 | RAG |
| 部件信息问题 | 组成、功能、关系 | 部件 | KG |
| 概念解释问题 | 定义、含义 | 已识别的概念 | RAG |
| 非动车检修问题 | 明显非领域问题 | 不适用 | OUT_OF_SCOPE |

明确询问原因优先于处置，询问“超过多少”按限度查询，不能当作已经超限。分类规则和完整性政策属于项目设计，需要通过更多真实问句持续验证。

## 实体标注

1. 只标注原文明确出现的部件、故障或现象、工艺、指标、数值、单位。不能把答案中的工艺写入输入实体。
2. 标注标准词使用terminology.json的键。原始表述保留原文；例如“轴箱”归一化为“轮对轴箱装置”。
3. 泛称不强行缩小：传感器不能直接变成速度传感器，减振器不能直接变成一系垂向减振器，探伤不能直接变成磁粉探伤。
4. 词典支持同一原文跨类别表达，如“划伤深度”同时包含故障“划伤”和指标“划伤深度”。同类别采用最长不重叠匹配。
5. 数值保留原文单位，不进行量纲换算；当前模型没有输出数值、单位与具体指标的绑定关系。复杂多值问题仍有局限。
6. `实体标注完整=false`表示只标了部分预期实体，评估检查覆盖。`true`表示全部实体已人工标注，评估计算集合完全匹配与micro P/R/F1。

## 数据版本与实验

- `questions.json`：40条开发题，标注2.0；修订理由在annotation_changes.json。
- `questions_holdout.json`：规则第一轮修改后编写的24条完整标注题，首次预测固定在evaluation/holdout_first。已暴露给开发过程，后续不能继续声称是未见测试集。
- `questions_regression.json`：上述24题复核后的回归版本，H015的高度标签修订为弹簧高度，原因写在样本中。
- `evaluation/baseline/original_rules.json`：修改前原始40题和预测。
- `evaluation/development_comparison.json`：使用同一套2.0标注比较39题；Q018改变了问句，排除比较。

本次独立题由同一开发者编写且数量较小，存在选择偏差。首次结果用于如实展示尚未针对这些题修复时的表现，回归结果用于证明修复，没有足够证据宣称生产级准确率。

## LLM调用

使用兼容OpenAI的chat/completions接口。Prompt列出8类意图、6类实体、路由和完整性约束，并附词典。输出需要通过JSON结构、枚举、原始词出处、路由一致性和置信度校验。失败最多尝试两次，最终回退到规则结果并标明来源。

2026-09-09：已配置DeepSeek并完成单题连通性测试。本地变量使用DEEPSEEK_API_KEY、DEEPSEEK_BASE_URL、DEEPSEEK_MODEL，密钥不入仓库。此前离线三模式实验仅证明回退有效，不代表在线模型质量。当前版本的24题在线批测尚待授权。

当前LLM模式在结构校验与术语归一化后，复用completeness.check和router.route，统一检索所需条件，避免模型强制索要确诊资料。批测中的完整性、澄清和路由是集成系统指标，不是独立LLM指标。

evaluation/recheck_20260909保存报告引用的规则开发与回归复测；evaluation/acceptance_20260909/ui_checks.json单独保留先前的页面交互检查。新增完整性准确率、澄清触发、澄清字段覆盖、实际来源计数、混淆矩阵、样本内容SHA-256及模型名。澄清字段覆盖仅为自动检查，不能代替人工审阅措辞是否合理。
