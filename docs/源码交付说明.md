# 源码交付说明

## 上传内容

源码压缩包包含main.py、app.py、config.py、core/、data/、tests/、evaluation/、requirements.txt、README.md、.env.example、.gitignore、LICENSE，以及doc/和docs/中的现行资料。tests/不是重复测试结果，删除它会使接收者失去复现检查的依据。

题集questions_holdout.json与questions_regression.json是首次和回归两个版本，不应合并或删除；annotation_changes.json说明标注变化。词典和来源记录是程序与验收所需数据，均应保留。

## 固定实验目录

- baseline/与development_comparison.json：原始基线及重评依据。
- holdout_first/：首次测试，不能被回归成绩替代。
- recheck_20260909/：正式报告使用的开发与回归复测，均时约0.69ms和0.84ms。
- acceptance_20260909/ui_checks.json：独立页面检查，保留其原始位置和耗时。
- offline_modes/：保留历史离线回退证据，不能当作在线模型性能对比。

旧acceptance开发/回归批测与regression_latest结果已经由报告所用复测替代，不在本版重复保留。CSV提供逐题表，JSON提供结构化结果和汇总，它们是不同查看方式，并非必须删除其中一种的重复文件。

## 不上传的本地内容

.env及其他真实密钥文件、.venv/、.git/、__pycache__/、.pytest_cache/、tmp/、output/、编辑器临时文件不进入源码包。`.env.example`仅含空密钥和配置示例，需要保留。不要为了压缩源码删除开发机上的虚拟环境或密钥；打包时排除即可。

结题报告、PPT、讲稿和截图单独上传到课程指定位置。老师参考范文、交接对话、排版预览、历史备份和打包验证文件不属于源码交付物。

## 解压验证

按README创建环境并安装requirements.txt，然后执行显式rules命令和 `python -m pytest tests -q`。新评估写到evaluation/local_development或evaluation/local_regression，不覆盖固定历史结果。核心规则测试不需要在线API。

## 仓库提交范围

提交现行源码、数据、测试代码和固定结果，以及本次README、.gitignore、接口、验收和交付文档调整；同时提交旧文件的删除记录。新增recheck_20260909的四个结果文件应纳入版本控制，因为正式报告引用了它们。压缩包在仓库外生成，无需把ZIP再提交进源码仓库。
