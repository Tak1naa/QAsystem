## 二、系统总体架构

### 2.1 定位

问题理解与处理建议系统位于完整智能问答系统的 **前置环节**，负责：

- 判断用户想问什么 **（意图识别）**
- 提取已包含的检修信息 **（槽位填充）**
- 指出缺失的必要信息 **（完整性判断）**
- 建议后续走哪个知识源 **（路由决策）**

### 2.2 流水线架构

```
用户输入 (自然语言问题)
        │
        ▼
┌───────────────────────────────────────────────────┐
│              Pipeline 流水线编排                    │
│                                                    │
│  ① 分类器 ──────▶ ② 提取器 ──────▶ ③ 标准化器      │
│      │                  │                 │         │
│      ▼                  ▼                 ▼         │
│  问题类型           已识别信息         标准化信息     │
│                                                    │
│  ④ 完整性检查 ◀──── 综合以上结果                    │
│      │                                              │
│      ▼                                              │
│  ⑤ 处理建议生成 (路由)                              │
│      │                                              │
│      ▼                                              │
│  统一JSON输出 ──▶  CLI / FastAPI / 前端页面          │
└───────────────────────────────────────────────────┘
```

### 2.3 两种运行模式

| 模式 | 实现方式 | 依赖 | 适用场景 |
|------|---------|------|---------|
| **纯规则模式** (默认) | 关键词匹配 + 术语词典 | 无外部依赖 | 本地运行、演示验证 |
| **LLM增强模式** (可选) | 调用大模型API辅助分类和提取 | OpenAI API / 兼容接口 | 提升准确率 |

两种模式通过配置开关 `use_llm_classifier` / `use_llm_extractor` 切换。LLM不可用时自动降级为规则模式。

## 三、核心模块设计

### 3.1 问题类型分类器 `classifier`

#### 3.1.1 问题类型定义（8类）

| 序号 | 类型标识 | 说明 | 典型问句模式 | PDF中的相关章节 |
|------|----------|------|-------------|----------------|
| 1 | `标准限度问题` | 询问具体数值标准、公差范围 | "×不超过多少？" "×的标准是多少？" | 4.2(板厚限度表)、4.3(过盈量)、4.8(裂纹长度) |
| 2 | `故障诊断问题` | 描述异常现象→推断原因/故障点 | "×有点响，可能是哪的问题？" "×发热什么原因？" | 4.3(轴承缺陷)、4.8(制动盘裂纹) |
| 3 | `工艺流程问题` | 询问检修操作步骤/方法 | "×怎么操作？" "×如何检修？" | 4.3(压装流程)、4.11(组装流程) |
| 4 | `部件信息问题` | 查询部件组成/功能/关系 | "×包括哪些部件？" "×有哪些部位？" | 4.1(转向架总体)、4.2(构架组成) |
| 5 | `超限处置问题` | 参数超过限度后如何处理 | "×超了怎么办？" "×大于标准值怎么处理？" | 4.2(缺陷深度超限换构架)、4.3(车轮报废) |
| 6 | `条件判断问题` | 满足某条件下该做什么操作 | "×小于×怎么办？" "满足×要更换吗？" | 4.3(车轮<800mm)、4.8(闸片<5mm) |
| 7 | `概念解释问题` | 询问术语/概念的含义 | "什么是×？" "×是什么意思？" | 4.8.1(发纹/裂纹定义)、探伤方法 |
| 8 | `非动车检修问题` | 与检修完全无关 | 天气、娱乐、购物等 | — |

#### 3.1.2 实现方案

**纯规则模式**：每类问题预设关键词列表 → 匹配打分 → 取最高分为分类结果
- 置信度 = 最高分类得分 / 总得分 + 0.1（上限0.95）
- 非检修关键词先过滤（如"天气""股票""火锅"），但需二次确认是否同时包含检修术语
- 兜底策略：未命中任何类型时，检查是否含领域术语→有则归为`故障诊断问题`(0.4置信度)，无则归为`非检修问题`(0.7置信度)

**LLM增强模式**：构建包含8类定义的prompt → 调用LLM → 解析JSON返回

### 3.2 关键信息提取器 `extractor`

#### 3.2.1 提取的5类信息字段

| 字段 | 含义 | 来源方式 | 示例值 |
|------|------|---------|--------|
| `部件` | 动车部件/装置名称 | 术语词典匹配 | 轮对轴箱装置、构架组成、制动盘 |
| `故障或现象` | 故障表现或异常现象 | 术语词典匹配 | 裂纹、异响、磨损、腐蚀 |
| `工艺` | 检修工艺/方法 | 术语词典匹配 | 磁粉探伤、焊修、压装、打磨 |
| `指标` | 检测指标名称 | 术语词典匹配 | 剩磁量、直径、厚度、扭矩 |
| `数值或单位` | 出现的数值和单位 | 正则提取 | 0.5mm、800KN、60°C、1200N·m |

#### 3.2.2 实现方案

**纯规则模式**：
- 4个语义类字段：遍历术语词典，在问题文本中做**最长匹配**（优先匹配长词，避免"轴"截断"车轴"）
- 数值/单位字段：正则匹配 `数字+单位` 模式，覆盖中英文双套单位（mm/毫米、MPa/兆帕）

**LLM增强模式**：在prompt中提供术语词典摘要 → LLM结构化提取 → JSON解析

### 3.3 术语标准化器 `normalizer`

#### 3.3.1 功能

将口语化/简称/别名 → 映射为规范术语，例如：

| 用户表述 | → 标准化 | 类别 |
|----------|---------|------|
| 轴箱 | 轮对轴箱装置 | 部件 |
| 有点响 / 有声音 | 异响 | 故障 |
| 生锈了 / 锈了 | 腐蚀 | 故障 |
| 探伤 | 磁粉探伤 | 工艺 |
| 装上去 / 安上 | 组装 | 工艺 |
| 刹车盘 | 制动盘 | 部件 |
| 剩磁 | 剩磁量 | 指标 |
| 拧紧力矩 | 扭矩 | 指标 |

#### 3.3.2 实现方案

从 `terminology.json` 构建 **别名→标准名** 反向索引表，O(1)查找。

### 3.4 信息完整性检查 + 澄清提示 `completeness`

#### 3.4.1 各问题类型的必填/建议字段

| 问题类型 | 必填字段 | 建议字段 |
|----------|---------|---------|
| 标准限度问题 | 指标 | 部件、数值或单位 |
| 故障诊断问题 | 部件、故障或现象 | — |
| 工艺流程问题 | 工艺 | 部件 |
| 部件信息问题 | 部件 | — |
| 超限处置问题 | 部件 | 指标、数值或单位 |
| 条件判断问题 | 部件 | 指标、数值或单位 |
| 概念解释问题 | — | — |
| 非检修问题 | — | — |

#### 3.4.2 完整性三级判定

| 级别 | 条件 | 处理方式 |
|------|------|---------|
| `完整` | 必填全有 + 建议全有 | 直接路由到下一步 |
| `基本完整` | 必填全有，建议有缺失 | 路由但标注信息可进一步补充 |
| `不完整` | 必填有缺失 | 产出澄清提示，路由到CLARIFY |
| `不适用` | 非检修问题 | 路由到OUT_OF_SCOPE |

#### 3.4.3 澄清提示模板

```python
CLARIFY_TEMPLATES = {
    "部件":   "请补充具体部件名称，例如：轮对轴箱、构架、制动盘、牵引电机等。",
    "故障或现象": "请描述具体的故障现象或异常表现，例如：异响、裂纹、磨损、发热等。",
    "工艺":   "请说明涉及的检修工艺，例如：探伤、焊修、打磨、压装、清洗等。",
    "指标":   "请补充具体检测指标，例如：剩磁量、直径、厚度、深度、压力等。",
    "数值或单位": "请补充具体数值和单位，例如：0.5mm、800KN、60°C等。",
}
```

拼接示例：
> 以上问题信息不全，请补充具体部件名称，例如：轮对轴箱、构架、制动盘、牵引电机等。请补充具体检测指标，例如：剩磁量、直径、厚度、深度、压力等。

### 3.5 处理建议生成器/路由器 `suggester`

#### 3.5.1 路由规则

```
                     ┌─────────────────┐
                     │  用户问题输入    │
                     └────────┬────────┘
                              │
                     ┌────────▼────────┐
                     │  非检修问题？    │
                     └────────┬────────┘
                         Y    │    N
              ┌──────────┐   │   ┌──────────┐
              │OUT_OF_   │   │   │ 信息完整？ │
              │SCOPE     │   │   └─────┬────┘
              └──────────┘   │    Y    │    N
                             │         │
                   ┌─────────▼──┐  ┌──▼──────────┐
                   │ 问题类型？   │  │  CLARIFY    │
                   └─────┬──────┘  │  引导补充信息 │
                         │         └─────────────┘
          ┌──────────────┼──────────────┐
          │              │              │
   故障诊断/部件信息   标准限度/工艺流程   │
          │         /超限处置/条件判断   │
          │         /概念解释           │
    ┌─────▼──────┐              ┌──────▼─────┐
    │    KG      │              │    RAG     │
    │ 查知识图谱  │              │查规程知识库 │
    └────────────┘              └────────────┘
```

#### 3.5.2 路由理由示例

| 标签 | 典型理由 |
|------|---------|
| `RAG` | "标准限度问题需要查找规程原文中的具体数值标准，适合进入规程知识库检索。" |
| `KG` | "故障诊断问题包含部件和现象，适合查询知识图谱中的现象-故障-原因关系。" |
| `CLARIFY` | "当前问题缺少部件和指标，无法判断应查规程原文还是知识图谱。" |
| `OUT_OF_SCOPE` | "该问题不属于动车检修规程问答范围，不进入检修问答流程。" |

## 六、评估方案

### 6.1 评估指标

| 评估维度 | 具体指标 | 计算方式 |
|----------|---------|---------|
| 问题类型识别 | **分类准确率** | 正确分类数 / 样本总数 |
| 问题类型识别 | **混淆矩阵** | 各类别间的错误分布 |
| 关键信息提取 | **字段召回率** | 各字段命中数 / 期望命中数 |
| 关键信息提取 | **标准化准确率** | 别名→标准名映射正确数 / 总映射数 |
| 信息完整性 | **判断准确率** | (正确判完整 + 正确判不完整) / 总数 |
| 处理建议 | **路由正确率** | 正确路由数 / 样本总数 |
| 处理建议 | **澄清合理性** | 缺失提示是否覆盖实际缺失字段 |
| 运行效率 | **各环节耗时(ms)** | pipeline内置计时器自动统计 |

## 七、拓展方向

| 序号 | 方向 | 具体内容 | 加分依据 |
|------|------|---------|---------|
| 1 | **LLM增强** | 将分类器和提取器切换为LLM模式，对比规则模式与LLM模式在各指标上的差异 | 有对比表和失败分析 |
| 2 | **前端高亮展示** | 在原始问题中使用颜色标注识别出的部件(蓝)、故障(红)、工艺(绿)、指标(橙)、数值(紫) | 高亮结果与结构化输出一致 |
| 3 | **运行耗时统计** | 分别记录纯规则模式 vs LLM模式各环节耗时(ms级)，产出耗时对比表 | 能分析影响响应速度的主要环节 |
| 4 | **准确性提升** | 丰富术语词典覆盖范围、优化关键词权重、引入上下文消歧(如动词优先判断问题类型) | 给出具体策略思路和前后准确率对比 |
| 5 | **完整前端页面** | 开发Web页面：输入框 → 结构化结果卡片(问题类型/识别信息/标准化/处理建议) → 原始问题高亮 | 页面完成完整演示 |
| 6 | **多分类器对比** | 对比纯关键词 vs 关键词+LLM vs 纯LLM三种分类策略的准确率和耗时 | 有对比表 |
